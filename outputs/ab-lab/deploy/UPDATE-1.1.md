# 1.1 更新：放行后手动切换 A / B

新的按钮位于「A/B 内容」页面顶部。

- 规则拦截：固定展示 A。
- 规则放行（含白名单）：展示你选择的 A 或 B。
- 点击按钮会回到规则模式，保留已有过滤条件和防护开关。若防护已关闭，所有访客跟随选择，界面会警告。
- 原有「全部访问 A/B」仍是全局强制模式，跳过规则；不要把两种切换混淆。
- 已发布内容不变，规则、账号、日志、计数不删除。已有配置缺少新字段时默认放行后展示 B。
- 只影响后续请求；已打开的访客页面需要刷新。

## 尚未安装到服务器

直接使用新的 `ab-lab-baota-v1.1.zip`，按 BAOTA.md 首次安装。旧安装包可保留作备份。

## 已按旧版说明安装到宝塔

不要重新运行首次安装脚本，不要覆盖 `/var/lib/ab-lab` 或 `/etc/ab-lab`。

1. 把新版解压到一个新的私人暂存目录（网站根目录以外）。
2. 停止 `ab-lab-admin`、`ab-lab-target` 服务。备份 `/opt/ab-lab` 以及整个 `/var/lib/ab-lab`，确认备份可读。
3. 从新版中复制以下文件到 `/opt/ab-lab` 的相同相对路径，保留 `.venv`、配置文件和运行数据：
   - `ablab/models.py`
   - `ablab/rules.py`
   - `templates/index.html`
   - `static/app.js`
   - `static/app.css`
4. 文件归 root 所有，普通程序文件权限0644、父目录0755；不要修改数据目录的服务用户所有权。这次没有新增依赖或 SQL 表结构迁移。
5. 重新启动两个服务，刷新后台页面；确认「A/B 内容」顶部出现新按钮。
6. 用一组允许和一组拦截条件验收：允许访客随按钮在 A/B 之间切换，拦截访客两次都仍是 A。检查日志原因，确认上传的旧内容和配置还在。

如需回退程序，旧版不认识 `allowed_slot` 新字段，不能只覆盖回旧代码。停止服务后连同升级前完整数据备份一起恢复，再启动验收；恢复数据会丢失备份后的新增操作，执行前先另存当前数据。没有授权时不要自动回滚或删除任何数据。

本轮只更新本机程序与发布包，未替你连接服务器执行升级。
