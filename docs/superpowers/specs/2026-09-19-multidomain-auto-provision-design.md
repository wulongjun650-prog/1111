# 多域名独立管理与宝塔自动接入方案

状态：用户已确认方案；开始本地实现与验证，不操作真实服务器。

## 1. 用户操作

程序仍只部署一套、一个管理员账号。后台增加「域名管理」：

1. 点击「添加域名」，填写自己拥有的完整域名。
2. 系统显示需要添加的 A 记录及安装时设置的服务器公网 IPv4 地址。
3. 用户到域名服务商处修改解析；程序不索取域名服务商账号，也不自动修改 DNS。
4. 后台任务检测解析，确认满足条件后自动在宝塔创建新站点和专属入口目录，接入现有分流服务并配置 HTTPS。
5. 后台显示真实的接入进度；域名具备独立的 A/B 内容、规则、切换状态、链接、计数、日志、发布历史。

只处理后台已登记的域名。陌生 Host 或仅仅把域名解析过来的第三方不能触发建站。第一版按用户填写的精确主机名接入，不自动扩展 www、泛域名或接入 CDN。

## 2. 架构选择

采用：一套应用 + 域名登记表 + 每站独立数据目录/SQLite + 单独运行的建站服务。

- 不为每个域名复制应用、虚拟环境或启动一组进程，减少这台小内存服务器的负担。
- 不把所有站点数据揉进现有表后依赖每条查询手动过滤，优先复用已测试的单站 Store，降低串站风险。
- 不让访客请求直接调用宝塔接口。Web 管理服务只登记任务，建站服务负责有限的自动操作。

备选方案：每域名部署完整程序，资源和升级成本较高；所有业务共用一份分区数据库，需要大范围重写现有查询。这两种方案不作为本次实现方向。

## 3. 数据和请求隔离

- 中央登记记录包含不可变站点ID、规范化域名、启停状态、接入阶段、宝塔站点ID、受管目录标记、重试时间及脱敏错误。
- 新站私有数据位于 `/var/lib/ab-lab/sites/<站点ID>/`，数据库、密钥和上传内容不置于可公开下载的根目录。
- 宝塔站点有独立入口目录，限定在安装时固定的专用父目录内，例如 `/www/wwwroot/ab-lab-sites/<站点ID>/`。入口目录用于域名验证和入口配置，不复制整套程序。
- 后台认证保持中央独立；站点选择不改变账号权限。
- 管理业务请求在路径中显式带站点ID；访客通过已登记且启用的规范化 Host 查找站点。Host 不用作任意文件路径。
- 预览签名、页面版本、计数和日志均按站点隔离。一个站点不能访问另一个站点的版本资源。
- 切换域名时处理未保存草稿；每个提交绑定点击时的站点ID，过期请求响应不能覆盖新站点页面。
- 已有单站数据登记为原站，保留原有页面、账号、规则和日志；迁移必须可重复执行且有备份，不悄悄迁移到新域名或覆盖已有内容。

## 4. 保留现有 A/B 行为

每个站点独立保留 v1.1 逻辑：

- 防护开启、规则模式：拦截固定展示 A；放行（含白名单）展示该站选择的 A 或 B。
- 防护关闭：该站所有访客跟随放行后的选择。
- 全局强制 A/B 的“全局”只指当前站点，不影响其他域名。
- 切换不重新上传、不重新发布，对后续请求生效；已打开页面需刷新。
- 新站初始为空，未发布时显示维护页；不自动复制其他站点的页面、日志、IP名单或敏感配置。

## 5. DNS 检测和接入状态

状态分开持久化：等待解析 → 检测通过 → 创建站点 → 配置入口 → 配置证书 → 验收中 → 已接入；另有失败待处理、已暂停。

- 安装时明确填写期望公网IP，不根据请求头、当前客户端IP或浏览器输入猜测服务器地址。
- 查询公共 DNS 的 A/AAAA，限制超时。A 地址必须符合配置的服务器地址，出现指向其他地址的 AAAA 或混合记录时给出明确提示，不贸然签证书。
- DNS 轮询在应用自带的后台建站服务中运行，不依赖本次聊天持续在线。
- 默认约60秒检查一轮；网络故障退避，持久化下一次尝试时间。证书失败不频繁重复申请，遵循供应商错误/限速响应。
- 检测到IP一致只代表解析条件满足，不代表 HTTPS 已可用。HTTP 验证、证书有效性和最终站点响应全部通过才标记完成。
- 连通性检查仅使用固定服务器地址、固定80/443端口和已验证域名，不抓取任意用户URL，不跟随到未知地址的重定向。

## 6. 宝塔自动建站边界

首次安装需要用户在服务器上一次性配置面板连接地址、API密钥/来源白名单、服务器IP及证书所需设置。此后添加域名无需逐个进入宝塔操作。

- 面板API权限通常很高；不宣称它天然具备本系统所需的细粒度权限。API密钥只由独立建站进程读取，后台页面、接口响应、日志和发布包均不包含它。
- 优先面板本机连接；跨网络连接必须校验 HTTPS 证书，不使用忽略证书错误的方式连接面板。
- 适配器仅暴露查站点、创建受管站点、配置受管入口、证书操作及验收能力，不暴露任意命令或任意文件路径给网页。
- 创建前检查域名是否已被面板中的任意站点/别名占用；有冲突就停止，不自动接管现有站点。
- 每步记录面板站点ID、受管路径和创建标记。超时后的重试先查询核对，不能盲目再次创建。发现未明确归属本系统的同名站点/目录时停止。
- 写配置前核对站点ID、域名、目录和所有权标记；仅修改本系统创建的站点。发现人工改动冲突时提示处理。
- Nginx 必须传递当前站点的真实 Host，同时由本机代理覆盖真实客户端IP和协议头。不能继续使用 v1.1 固定单个访客域名的模板。
- HTTP 验证路径独立于A/B分流、国家/设备/爬虫规则与登录，避免本应用阻断证书申请和续期。
- 新配置检查成功后才能重载；失败保留已有站点和任务记录，不自动删除目录或全局回滚面板。
- 首版提供暂停、重试和查看错误，不提供自动删除宝塔站点、清空目录或批量覆盖已有站点。

## 7. HTTPS与版本兼容

已核实 aaPanel 当前公开网站接口文档包含创建站点时指定根目录及申请SSL的参数，以及SSL查询/部署相关接口。但这不等于已验证用户截图中8.0.4环境的完整兼容性；宝塔中文版和aaPanel的接口响应也不能混为一谈。

实现时分别定义明确的适配契约。首次启用自动接入前做只读版本/接口能力检查，只有确认静态或反代站点、证书和配置检查能力的版本才开启自动写入。不能凭猜测使用未确认的PHP版本值、接口路径或响应成功标志；不兼容时展示具体原因，不伪装成功。

证书优先由面板已有的自动证书流程管理；签发与续期需要实际验证。HTTP-01要求80端口验证路径可访问；仅改A记录并不保证签发成功。证书服务条款、联系邮箱等需由用户在服务器初始化时确认，不代用户接受新的法律协议。

## 8. 后台界面

- 域名列表：域名、解析目标、接入阶段、证书状态、启用状态、失败原因。
- 添加对话框：精确域名输入与校验，提交后展示可复制的解析信息。
- 站点选择器：明确当前正在编辑的域名；概览、A/B内容、规则、模拟、日志随站点切换。
- 接入日志：展示阶段和可操作错误，不输出API密钥、认证签名或完整面板响应中的敏感字段。
- 未连接面板的本地环境允许测试登记和数据隔离，但自动接入明确显示“未配置”，不得显示假证书或假建站成功。

## 9. 验证与交付

1. 先增加失败测试：两个域名配置不同规则和A/B版本，同一IP的计数互不影响，跨站资源/预览不能互读。
2. 验证迁移幂等、旧站数据保留、规范化域名、重复登记、保留域名/非法Host拒绝。
3. 用受控面板接口测试服务验证任务状态、重试、超时后核对、已有站点冲突、错误脱敏和证书失败；不把这些测试当成真实面板联调。
4. 回归原有上传、认证、CSRF、规则与v1.1切换测试；浏览器实测站点切换和新域名流程。
5. 交付新版源码、独立发布包、升级/备份说明和首次连接向导。旧包保留，不覆盖用户服务器。
6. 真正发布前还必须在用户的具体面板版本上完成受控域名的建站、证书、重启恢复和其他站点无影响验收。没有这一步不能声称已实现“在你的宝塔验证成功”。

## 10. 范围限制与参考
