# A/B 安全实验平台设计规格

日期：2026-09-02

## 1. 目标

构建一套供单个管理员自用的 A/B 静态页面安全实验平台。平台接收 A、B 两个 ZIP 静态站点包，通过一个目标域名展示内容，并支持三种运行状态：

- `规则模式`：未通过访问规则的请求显示 A，通过规则的请求显示 B。
- `强制 A`：所有请求显示 A。
- `强制 B`：所有请求显示 B。

系统采用安全基线设计，用自动化测试验证攻击被拦截，不在可部署程序中提供故意关闭安全控制的“漏洞开关”。

## 2. 已确认约束

- 只有一个管理员，不开放注册、团队、角色权限或多租户。
- 开发技术为 Python、FastAPI、SQLite、服务端 HTML 模板。
- 最终部署环境为 Linux、宝塔、Nginx；当前阶段先在本地开发。
- A/B 内容以 ZIP 上传，每个包必须包含入口 `index.html`。
- 页面可包含 HTML、CSS、图片、字体、浏览器端 JavaScript 和表单。
- ZIP 内不允许 PHP、Python、Shell、二进制程序或符号链接。
- 管理后台与目标页面在安全边界上分离；部署时使用不同子域名。
- 未通过规则的访问不会收到空白、403 或 404，而是显示 A 页面。

## 3. 非目标

第一版不包含：

- AB 链接跳转或反向代理到外部网站。
- 多管理员、注册、找回密码、团队协作和计费。
- React、Vue 等独立前端工程。
- Redis、消息队列或 MySQL。
- 大规模流量优化和多服务器同步。
- 绕过第三方平台审核或对未授权系统进行测试。

## 4. 总体架构

系统是一个 FastAPI 应用，内部按职责拆分为管理端、目标站点、上传服务、规则引擎、页面仓库和审计服务。

```text
管理员浏览器
    -> 管理端（认证、上传、预览、规则、模式切换、日志）
    -> SQLite（配置、版本元数据、审计与访问记录）
    -> 文件存储（不可变的 A/B 页面版本）

访客请求
    -> 可信客户端 IP 解析
    -> 设备、国家、IP、爬虫规则引擎
    -> 规则模式 / 强制 A / 强制 B
    -> 安全路径解析
    -> 返回所选版本的静态文件
```

开发环境允许使用不同主机名或端口模拟管理域名和目标域名。部署时，Nginx 将 `admin.example.com` 和 `target.example.com` 转发到同一应用；应用同时校验 `Host`，避免管理路由出现在目标域名。

## 5. 页面与版本存储

```text
data/
├── app.db
├── pages/
│   ├── A/<version-id>/
│   └── B/<version-id>/
├── staging/<upload-id>/
└── quarantine/<upload-id>/
```

- 每次成功上传产生一个不可变版本，禁止覆盖已有版本。
- A、B 各有一个当前发布版本指针。
- 上传文件先进入 `staging`，验证失败时移动到隔离记录后删除；验证成功后以原子重命名方式发布。
- 页面版本记录槽位、版本 ID、创建时间、文件数量、解压后总大小、SHA-256 摘要和状态。
- 回滚只改变对应槽位的当前版本指针，不复制文件。
- 页面目录不放在 Nginx 可直接访问的公开根目录，由应用执行规则后返回文件。

## 6. ZIP 安全导入

导入过程按固定顺序执行，任何步骤失败都不会产生可发布版本：

1. 校验请求大小和 ZIP 文件签名，不只依赖扩展名。
2. 限制压缩包大小、成员数量、单文件大小和解压后总大小。
3. 拒绝绝对路径、盘符、`..` 路径、重复规范化路径和空文件名。
4. 拒绝符号链接、硬链接、设备文件和其他非普通文件。
5. 使用扩展名与内容类型允许列表，仅接受静态网页资源。
6. 拒绝服务器端脚本、可执行程序和危险配置文件。
7. 解压到随机 staging 目录，并再次确认每个解析后路径仍位于 staging 内。
8. 要求根目录存在 `index.html`；如果 ZIP 只有一个外层目录，则安全地剥离该单层目录。
9. 计算清单与摘要，原子移动到最终版本目录。

第一版的默认限制为：ZIP 最大 20 MiB、最多 500 个文件、解压后最大 100 MiB、单文件最大 20 MiB。限制可在服务器配置中收紧，但不能从公开请求中覆盖。

## 7. 访问决策

### 7.1 三种运行状态

- `RULES`：只有所有启用的允许条件通过，且没有命中拒绝条件时选择 B；其他情况选择 A。
- `FORCE_A`：跳过分流规则并选择 A。
- `FORCE_B`：跳过分流规则并选择 B。

模式切换和版本指针更新使用单个 SQLite 事务。每次切换记录旧值、新值、时间和管理员会话标识。

### 7.2 规则优先级

规则引擎按以下顺序评估，并返回可解释的原因列表：

1. IP 明确黑名单。
2. IP 明确白名单。
3. 已知或声明的爬虫规则。
4. 国家/地区规则。
5. 设备类型规则。
6. 可选浏览器、语言和时间规则。

黑名单始终拒绝进入 B。白名单可配置为直接允许 B，默认仍需通过其他规则。无法识别的国家、设备或爬虫身份按“不通过”处理并显示 A。

### 7.3 可信 IP

- 默认只使用 TCP 对端地址。
- 只有请求来自配置过的 Nginx/反向代理地址时，才读取转发的客户端 IP。
- 不信任来自任意公网客户端的 `X-Forwarded-For` 或类似请求头。
- 规则模拟器使用独立的管理员接口，不允许访客通过请求头开启模拟模式。

### 7.4 国家与设备

- 国家识别通过可替换的本地 GeoIP 提供器完成；开发和测试使用确定性的假数据提供器。
- GeoIP 数据库缺失或查询失败时返回 `unknown`，规则模式显示 A，并在后台显示健康告警。
- 设备识别基于 User-Agent，只作为实验规则，不宣称能抵抗主动伪造。

### 7.5 爬虫识别

- 第一版支持可配置的 User-Agent 特征和 IP/CIDR 列表。
- 对声称为 Google 等搜索引擎的请求，可选执行正向/反向 DNS 一致性验证并缓存结果。
- User-Agent 可以伪造，因此后台明确区分“声明的爬虫”和“网络验证的爬虫”。
- 该功能用于授权靶机实验和自身平台审核，不作为规避第三方审核的保证。

## 8. 静态内容返回

- 每个目标域名请求都先经过访问决策，再在所选版本目录内解析路径。
- URL 路径经过一次严格规范化；解析后的文件必须仍位于版本根目录。
- 目录请求只允许解析到 `index.html`，不存在的资源返回 404，不回退到另一个槽位。
- 响应设置正确的静态内容类型、`X-Content-Type-Options: nosniff` 和明确的缓存策略。
- 第一版由 FastAPI 返回静态文件，以保证所有资源请求都经过同一规则；未来可在不改变接口的前提下改用 Nginx 内部转发。
- 模式或版本切换后，新请求立即使用新状态。切换瞬间已经开始加载的旧页面不保证跨多个资源请求形成一致快照，这是单机第一版接受的边界。

## 9. 表单与浏览器脚本

- 上传页面中的浏览器端 JavaScript 可以运行，但不能获得管理域名的 Cookie 或 DOM。
- 管理后台中的预览使用目标域名上的短期签名 URL，并放入 sandbox iframe；允许脚本和表单，不授予同源权限。
- 页面可以向其声明的 HTTPS 地址提交表单。
- 第一版提供可选的本地实验收集端点，只接受限量的表单字段，不接受文件，不记录 Cookie、Authorization 或密码字段，并提供一键清空。
- 本地收集端点只用于靶机验证，不作为业务数据收集系统。

## 10. 管理后台

管理后台包含：

- 单管理员登录、退出和修改密码。
- 首次启动通过命令行创建管理员，不提供公开初始化页面。
- A/B 上传、验证结果、预览、发布、版本列表和回滚。
- 三种运行状态切换，并在首页醒目标识当前状态。
- IP、国家、设备和爬虫规则配置。
- 规则模拟器：输入实验 IP、国家、User-Agent 和时间，返回槽位与逐条判定原因。
- 访问日志、上传日志、登录日志和切换审计。
- 系统健康状态：数据库、页面版本、GeoIP 数据与磁盘空间。

管理操作均使用 POST/PUT/DELETE 语义，要求有效会话和 CSRF 令牌。危险操作需要二次确认，但不要求重复输入密码。

## 11. 认证与会话

- 密码使用现代自适应密码哈希算法保存，不保存明文或可逆密码。
- 会话标识使用高熵随机值，服务端保存会话摘要和过期时间。
- Cookie 设置 `HttpOnly`、`Secure` 和 `SameSite=Strict`，并只作用于管理子域名。
- 登录失败采用逐步延迟和 IP/账户组合限速。
- 修改密码和手动退出会撤销全部现有会话。
- 应用密钥和管理员初始密码通过环境变量或交互式命令提供，不提交到仓库。

## 12. 数据模型

SQLite 至少包含以下表：

- `settings`：运行状态、配置版本和更新时间。
- `page_versions`：A/B 槽位、版本目录、摘要、大小、状态和时间。
- `slot_assignments`：每个槽位当前发布版本。
- `access_rules`：规则类型、动作、值、启用状态和顺序。
- `admin_users`：唯一管理员及密码哈希。
- `sessions`：会话摘要、创建时间、过期时间和撤销状态。
- `audit_events`：登录、上传、发布、回滚、切换和规则修改。
- `access_events`：请求时间、匿名化 IP、规则结果、槽位和原因代码。
- `form_events`：可选实验表单记录，采用严格大小与字段限制。

数据库开启外键约束和 WAL 模式。访问日志设置保留期限，避免数据库无限增长。

## 13. 错误处理

- 上传验证错误向管理员显示明确原因，但不暴露服务器绝对路径。
- 数据库写入失败时不改变当前发布状态。
- 当前所选槽位没有有效版本时返回固定的安全维护页，并触发健康告警。
- GeoIP、DNS 或日志写入失败不能导致 B 被错误放行；规则模式采用保守结果 A。
- 静态文件路径异常、非法编码和目录越界统一返回 404，并记录原因代码。
- 管理端异常返回通用错误页和关联事件 ID，详细堆栈只写入服务器日志。

## 14. 安全测试策略

测试分为单元、集成和端到端三层：

- ZIP：路径穿越、绝对路径、符号链接、重复路径、压缩炸弹、扩展名伪装、缺少入口文件。
- 路径：编码绕过、双重编码、分隔符差异、目录访问和不存在资源。
- 认证：密码哈希、会话撤销、CSRF、Cookie 属性、登录限速和未授权管理请求。
- 规则：黑白名单优先级、未知 GeoIP、伪造转发头、设备识别、爬虫身份和三种运行状态。
- 切换：并发读取、事务失败、版本缺失、回滚和切换审计。
- 隔离：预览页面无法读取管理会话，目标域名无法访问管理路由。
- 日志：敏感字段脱敏、保留期限和失败不影响主请求。

测试只针对本项目的本地实例或明确授权的靶机环境，不包含对第三方站点的主动扫描。

## 15. 部署边界

- Nginx 终止 HTTPS，并分别代理管理子域名和目标子域名。
- FastAPI 进程以非 root 专用用户运行。
- `data` 目录归应用用户所有，页面版本不可由 Web 请求直接修改。
- Nginx 不为页面目录配置 PHP 或其他解释器。
- 管理子域名可额外使用宝塔/Nginx IP 白名单或 VPN 限制。
- 备份包含 SQLite 数据库和页面版本目录；恢复时验证版本摘要。
- 生产配置拒绝调试模式、默认密钥、宽泛可信代理和未加密管理访问。

## 16. 第一版验收标准

第一版完成时应满足：

1. 管理员可以安全登录并上传合法的 A.zip 与 B.zip。
2. 非法 ZIP 不会在页面目录外创建或覆盖任何文件。
3. 管理员可以预览、发布、回滚 A/B 版本。
4. 三种运行状态按定义工作，切换操作有审计记录。
5. 规则模式能够基于可信 IP、国家、设备和爬虫规则选择 A/B，并解释原因。
6. 目标页面及其静态资源可以正确加载浏览器端 JavaScript 和普通表单。
7. 管理后台与测试页面在 Cookie、主机和预览上下文上隔离。
8. 核心攻击测试全部自动化并通过。
9. 项目包含本地运行说明、测试命令和宝塔/Nginx 部署说明。
