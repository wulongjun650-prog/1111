# 独立证书与续期设计

日期：2026-09-21

状态：用户于 2026-09-21 确认本文具体设计，进入实施。未安装客户端、注册账户、申请证书或修改服务。

## 目标与选择

继续使用既有宝塔建站适配器和固定站点 ID，不调用宝塔证书申请、同步、部署或续期开关。首次签发和后续续期只管理 AB Lab 新建并确认归属的站点。

采用 Certbot 的 `certonly --webroot`，证书服务拟使用 Let's Encrypt。相比继续使用宝塔共享证书流程，这需要独立客户端和定时服务，但不接入宝塔跨站证书复制。相比自行实现 ACME 协议，复用成熟客户端可减少协议维护和密钥处理代码。

客户端安装来源、实际版本和所需参数必须在部署时验证；不根据参考文档版本声称服务器已具备能力。

## 目录和权限

- `/var/lib/ab-lab-certificates/production/` 和 `/var/lib/ab-lab-certificates/staging/` 分开保存生产与测试账户、证书、日志、工作目录；不使用默认 `/etc/letsencrypt` 或宝塔的证书目录。
- 每个环境使用明确的 `--config-dir`、`--work-dir`、`--logs-dir` 和本系统私有 CLI 配置；证书名为 `ab-<32位站点ID>`，只申请该站点的精确域名，不自动加入 www 或泛域名。
- 管理目录由特权服务持有，模式 0700，私钥 0600；网页服务仍以 `ab-lab` 运行，不能读私钥、账户密钥或证书命令配置。
- HTTP 验证文件仅写入既有固定入口目录 `/www/wwwroot/ab-lab-sites/<ID>/.well-known/acme-challenge/`；无需 DNS 供应商密钥。
- Certbot 自己生成的 live/archive 链接只在证书专用读取器内允许：解析后的目标必须留在对应环境、对应证书的 archive 目录，拒绝跨站或逃逸链接。不要放宽现有 Nginx 配置路径的符号链接禁令。

## 签发与部署流程

1. 继续使用 DNS、根域名/子目录绑定、目录及私有任务记录的归属检查。已有站点不自动接管，原测试站点也不例外。
2. 在已创建站点的 HTTP 入口保留独立 ACME 验证路径。申请前验证该路径可达，不将 HTTP 可达视为上线成功。
3. 实际注册账户前向用户展示当时有效的 CA 服务条款并取得明确同意；账户邮箱由用户提供，不从日志或其他账户推断。此次架构批准不是接受 CA 条款。
4. 固定参数启动 Certbot，仅使用 webroot authenticator，不使用 Nginx installer、standalone、手工 DNS 或用户输入的 shell hooks。采用参数数组、受控环境和超时；禁止 shell 拼接、关闭 TLS 校验、无限重试和日常强制续期。
5. 每次写操作前核对归属，延续现有“先持久化签发意图”的策略。超时/崩溃后检查已有证书和任务，不盲目重发订单；缺少确认结果时保留待人工核对状态。
6. 校验证书域名集合、有效期、公私钥匹配、完整证书链与受控路径；测试证书不能用于生产部署，也不能让站点进入 active。
7. 将通过校验的证书复制到独立、不可变的部署版本目录。Nginx 指向已验证版本，不直接跟随 Certbot 会变化的 live 链接。
8. 只改本系统拥有且未被人工改动的站点配置。复用现场备份、pending 标记、`nginx -t` 和归属复核；验证通过才 reload。Nginx reload 是共享进程操作，不能宣传为绝对不影响其他站点。
9. HTTPS 证书验证、域名路由响应和续期演练全部通过，才使站点 active。命令退出码 0 不是证书已更新的充分证据。

## 续期与故障恢复

- 使用独立 systemd timer，每日两次检查，带随机延迟。只枚举私有任务记录里已确认归属的站点；逐个以固定 cert-name 续期，不扫描/接管其他客户端的证书。
- 与建站工作进程共用操作锁，阻止签发、续期和配置提交并发。Certbot 自带的锁不能替代系统的归属和并发检查。
- 不继承全局 CLI 配置或目录 hooks；启用 `--no-directory-hooks`，拒绝专用续期配置中不属于预期 webroot 模式的 installer、hook 或未知关键选项。
- 续期结束后比较证书指纹，只有真实发生变化且校验通过才部署新版本、检查并重载。无变化不重载。
- 失败时保留当前 Nginx 使用的有效证书和配置，记录脱敏错误及到期状态。发布结果不明时保留现场，不自动删除证书、撤销证书、清空账户或恢复其他站点。
- 暂停站点会停止后续签发/续期写操作；界面需明确暂停可能导致证书到期。已发送的远程请求无法由暂停撤销。

## 与现有组件连接

- 新增独立证书组件，负责受控命令、目录校验、证书检查和续期判断，不持有宝塔 API 密钥。
- `ManagedPanel.certificate()` 调用证书组件并提交该站点的 HTTPS 配置；`verify()` 收集真实 HTTPS、路由和续期证据。当前报“尚未完成”的方法只有在这些行为实现并通过验收后才能替换。
- 保留 `ProvisioningWorker` 的未知结果不盲重试、私有 SQLite、全局锁及暂停行为。新增证书状态只进入私有记录，不把私钥或账户信息写到网页可写登记表。
- 增加独立特权 worker 和续期服务部署配置，与现有网页服务账号隔离；不通过放宽网页服务权限实现建站。

## 验收标准

先本地测试（外部进程/CA 为替身，文件与证书校验用真实测试数据），再 Linux 隔离目录测试，最后指定域名的 staging 演练和正式签发。覆盖超时恢复、域名错误、路径逃逸、密钥不匹配、未知 hook、无变化续期、证书更换、Nginx 检查失败、暂停和进程中断。

只有受控真实建站、正式 HTTPS 路由、证书更新后重载与续期演练都通过，才发布自动建站版本。删除重建已有测试站点仍须先备份并取得具体操作确认；本方案不授权删除。
