# BaoTa deployment implementation plan

Goal: Ubuntu26.04 x86_64 BaoTa-compatible deployment package, independent admin HTTPS origin and target HTTPS origin, no actual server mutation.
Architecture approved in chat: existing FastAPI/SQLite services behind Nginx, systemd supervision, single account/password login without CAPTCHA. No Docker/billing/multiuser.

Global constraints: never include credentials; installer prompts with getpass, root-only config and service-user data. Existing25 sites untouched. No public upstream listeners. Nginx overwrites forwarded IP/proto; application trusts only loopback reverse proxy. Public mode refuses missing credentials/config/HTTPS origins. Local mode preserved.

1. Create settings.py/auth.py and tests/test_production.py. Config validates HTTPS origins with different hostnames, loopback proxy, auth preprovision required. Password scrypt, hashed expiring session tokens, per-session CSRF, SQLite-backed login throttling, logout/reprovision revocation. RED tests then implementation.
2. Extend web.py/run.py with optional deployment settings, production boundary middleware (reuse body/header protection), login/logout routes/templates/static/login.js. Keep target independent. API auth+origin+nonce checks, secure host-only cookie. Real IP from explicit trusted proxy only. Run existing and production tests.
3. Create deploy/configure.py, install.sh and deployment guide. Configure prompts privately, generates env-independent root-owned config, two service units and two Nginx location fragments. Installer checks Ubuntu/Python>=3.12, paths outside website root, non-root dedicated user, existing install refusal, no download-and-execute script. Generated fragments are pasted into explicitly chosen BaoTa sites, TLS managed by panel. Do not autoedit/reload Nginx.
4. Test generated artifacts in temporary folders, bash syntax where available, full Python/node suites; local UI regression; ZIP package clean of secrets/data. State plainly Ubuntu/BaoTa integration requires real server acceptance (Windows environment cannot prove systemd/nginx run).

Progress: implemented steps 1–4 for the local deliverable. 68 Python tests and 5 Node tests pass; script syntax and compile checks pass. Public domains are supplied during installation, not invented. Installer and guide do not modify any BaoTa site automatically. Real Ubuntu/systemd/Nginx/TLS acceptance remains explicitly unverified and is not part of this no-server-mutation turn. Independent reviewer unavailable; self-review plus automated regression performed.
